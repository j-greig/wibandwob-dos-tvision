Only record gotchas and information that would not be obvious from a quick exploration of the filesystem.

- Don't tell the user what you are going to do next; act. Report findings and results.
- Build the app with `cmake --build build --target wwdos -j 8`. The default build includes tests; `command_registry_test` and `scramble_engine_test` currently fail to link against missing application symbols. A leftover CMake cache does not imply generated build files exist: rerun README configuration if Makefile is missing.
- The desktop runs without the Python API. Use a real terminal or persistent tmux session, and redirect stderr to a log so diagnostics do not corrupt the display. Check existing sessions before launching another desktop.
- Launch scripts have side effects: `scripts/dev-start.sh` restarts instance resources and removes its socket; `start_api_server.sh` kills listeners on its configured port. To add API control to an existing desktop, run from repo root in a separate persistent session:
  ```sh
  WIBWOB_INSTANCE=1 WIBWOB_REPO_ROOT="$PWD" tools/api_server/venv/bin/uvicorn tools.api_server.main:app --host 127.0.0.1 --port 8089
  ```
  Match `WIBWOB_INSTANCE` to the desktop (`/tmp/wibwob_1.sock` for instance 1). Install the API requirements into its venv first.
- Keep the MCP dependency constraint: `fastapi-mcp==0.4.0` requires MCP SDK 1.x. SDK 2.x crashes startup with `Server.__init__() takes 2 positional arguments but 3 were given`.
- REST and streamable HTTP MCP (`/mcp`) control the live desktop. `/health` proves only API liveness; verify `/state` and a visible operation. Read the live canvas dimensions before arranging windows.
- `/windows/{id}/move` was observed ignoring `w`/`h` for a text editor. Use `/menu/command` with `{"command":"resize_window","args":{"id":"…","w":"…","h":"…"}}` and verify state. Some apps ignore titles supplied during creation; the registry exposes `window_title`.
- ASCII collages need `open_primer` (a `frame_player`), not `text_view`: the latter wraps UTF-8 art, shows guidance comments, and inherits the desktop texture. `open_primer` accepts explicit `x,y,w,h` and `title`.
- Window choreography: `scripts/artwork-window-show.py` runs a 30-second DVD bounce, cat counterpoint, and group sway, restoring positions/stacking afterward. Native IPC `get_state` has flat `x,y,w,h` fields; REST nests them under `rect`. A 30 fps target measured 18.5 updates/sec overall, with p95 control work 175 ms when moving multiple windows sequentially. Prefer few moving windows; do not promise smooth 30/60 fps from repeated API calls. Discover live IDs each run.
- FIGlet setters (`figlet_set_text/font/color`) resolve their `id` by window title or `auto`, not the `wNN` registry ID used for movement. `scripts/figlet-say-show.py` displays each word then waits for macOS `say` to finish it; this is word-level sequencing, not audio-clock synchronization.
- Replay the collage performance with `python3 scripts/wibwob-demo.py`; its cue score is `scripts/wibwob-demo.json`. Requires the running collage and macOS `say`. FIGlet stays white on black. The show closes its new windows and restores original positions/stacking on exit; it does not overwrite the workspace. The standalone `window-pixel-show.py` intentionally leaves its tiny-window installation open.
- Voice canon verified in heartbeat's `scripts/library-watching.scpt.md`: Wib = `Sandy (English (UK))`, Wob = `Grandpa (English (UK))` (use full voice names). User auditioned and approved **200 WPM for both**; 90 was too slow and 275–300 too fast. Use `say -v 'Sandy (English (UK))' -r 200` / `say -v 'Grandpa (English (UK))' -r 200`, including letter/cat cues. `demo_audio.py` adds macOS playback tied to window events, not a native app sound engine. Music defaults to heartbeat's `output/kibble-sommelier/audio/02-kibble-dnb.mp3`; override with `WIBWOB_DEMO_MUSIC`.
